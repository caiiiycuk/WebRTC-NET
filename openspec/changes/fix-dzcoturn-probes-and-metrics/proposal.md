# Proposal

## Why

При восстановлении TURN 11.11.2026 тестер из образа `4.18.0-3` получил все TLS-данные, но сообщил потери: его `SSL_read` объединил несколько TURN frames, а обработчик посчитал результат одним сообщением. Инструкции dzcoturn не проверяют внешнюю передачу UDP/TLS, предлагают удаление постоянного состояния при переходе со staging и описывают только локальные метрики, тогда как требуется внешний Prometheus.

## What Changes

- Исправить TLS framing в `turnutils_uclient` внутри `3rdparty/coturn`: обрабатывать объединённые и разделённые frames без потерь хвоста, с ограниченным буфером и регрессионными тестами. Увеличение интервала отправки не считается исправлением.
- Поставлять исправленный тестер через новый явно закреплённый образ форка. Сохранить соответствие commit submodule и release tag образа; не переиспользовать опубликованные версии.
- **BREAKING**: изменить default `prometheus-address` с `127.0.0.1` на `0.0.0.0`, сохранив порт `9641` и локальный scrape publisher. Документировать HTTP без авторизации, ограничение firewall по адресам мониторинга и возможность явно вернуть loopback в шаблоне.
- В README описать внешние UDP/TLS relay-проверки с положительными равными счётчиками отправки/получения и нулевыми потерями. Разделить несовместимый старый тестер, ошибку TLS framing и неисправность сервера; pacing оставить только обходом для прежних образов. Исправить в troubleshooting упоминание порта `443` для TURNS на `5349`, сохранив `8000` для HTTPS ping.
- Исправить инструкции backup/restore и staging → production в README и выводе `init.sh`: сохранять `.env`, сертификаты и весь `coturn-data`, включая историю capacity и traffic; не предлагать `down -v`, удаление `.env` или повторную инициализацию прежней identity.

## Capabilities

### New Capabilities

- `turnutils-tls-framing`: корректная обработка потока TLS тестером TURN, включая фрагментацию, объединение сообщений и безопасное завершение соединения.

### Modified Capabilities

- `coturn-docker-image`: внешний Prometheus по умолчанию, поставка проверенного тестера и эксплуатационные инструкции, проверяющие relay и сохраняющие состояние.

## Impact

- Форк: `3rdparty/coturn/src/apps/uclient/uclient.c`, состояние соединений в `session.h` при необходимости, ближайшие C-тесты и `tests/CMakeLists.txt`.
- Обёртка: `coturn-docker/Dockerfile`, `turnserver.conf.template`, `README.md`, справочный вывод `init.sh`, тесты конфигурации и интеграционные проверки. `publisher.py`, формат публикаций, квоты, порты TURN и правила истории capacity не меняются.
- Сборка и поставка: Linux `amd64` для образа; обязательные сборки Linux-целей HumbleNet и `emscripten/ninja -j32 webrtcnet`. Существующий change `harden-capacity-history-against-deadline` не изменяется.
- В scope входит подготовка нового образа и согласованного pin; публикация тегов/образа/архива требует отдельного разрешения. Публикация GitHub wiki и деплой на работающие серверы не входят. Изменения проекта cloud, firewall VPS, DNS, секретов и старых release assets не входят.
