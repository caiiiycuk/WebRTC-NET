# Spec Delta

## ADDED Requirements

### Requirement: История capacity не зависит от адреса публикации

Publisher SHALL принимать корректную сохранённую историю capacity того же `DOMAIN` независимо от совпадения текущего `PUBLISH_URL` с сохранённым `binding.publishUrl`. Он MUST сохранять `attemptedThroughMs`, отправлять публикации на текущий настроенный URL и не требовать ручного редактирования истории или повторной инициализации при смене URL. Существующие файлы версии 1 SHALL оставаться читаемыми без предварительной миграции.

#### Scenario: Смена URL при существующей истории
- **WHEN** publisher запускается с другим корректным HTTPS `PUBLISH_URL`, а файл версии 1 содержит историю того же `DOMAIN` и положительный watermark
- **THEN** история принимается без сброса watermark
- **AND** публикации направляются на текущий `PUBLISH_URL`
- **AND** смена URL сама по себе не отключает capacity

#### Scenario: История ещё не содержит попыток capacity
- **WHEN** корректный файл того же домена содержит `attemptedThroughMs=0` и другой сохранённый URL
- **THEN** publisher может опубликовать свежий корректный `known` без повторной инициализации

### Requirement: Смена URL сохраняет защиту истории capacity

При смене URL publisher MUST сохранять проверки домена, версии, целочисленного допустимого watermark, целостности файла и изменений состояния извне. Он SHALL сохранять существующие проверки HTTPS, свежести метрик, квот и сохранения watermark до отправки `known`. После перезапуска с положительным watermark publisher MUST публиковать `unknown`, пока нет здорового снимка со строго большим watermark; смена URL не разрешает повторно объявлять старый снимок `known`.

#### Scenario: Перезапуск с положительным watermark
- **WHEN** после смены URL publisher восстановил положительный watermark, а здоровый источник ещё не предоставил строго более новую отметку
- **THEN** capacity остаётся `unknown` с сохранённым барьером
- **AND** при появлении строго более нового здорового снимка его watermark надёжно сохраняется до отправки `known`

#### Scenario: История относится к другому домену
- **WHEN** домен сохранённой истории не совпадает с текущим `DOMAIN`
- **THEN** публикация `known` отключается независимо от URL
- **AND** история не переинициализируется автоматически

#### Scenario: История отсутствует или повреждена
- **WHEN** файл отсутствует, повреждён или содержит недопустимую версию либо watermark
- **THEN** publisher не создаёт новую историю автоматически и не публикует `known`
- **AND** ICE и трафик могут публиковаться по существующим правилам

#### Scenario: Изменение файла во время работы
- **WHEN** сохранённое состояние изменилось извне после его принятия publisher
- **THEN** publisher отключает `known` по существующим правилам
- **AND** разрешение менять настройку URL не отменяет контроль целостности файла

#### Scenario: Непригодный источник или адрес
- **WHEN** новый адрес нарушает проверку HTTPS либо метрики не проходят существующие проверки свежести и квот
- **THEN** смена URL не позволяет обойти соответствующую проверку
